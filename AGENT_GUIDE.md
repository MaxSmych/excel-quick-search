# AGENT_GUIDE — Быстрый поиск в Excel (Excel Search)

Единый источник правды по проекту. Главнее README.txt. При расхождении — верить этому файлу.

## Что это
Standalone desktop-утилита live-поиска по любому Excel-файлу (`.xlsx` / `.xls` / `.xlsb`)
с выбором отображаемых колонок, пофильтрами по колонкам, подсветкой совпадений и экспортом CSV.
Одно окно, один скрипт, без клиент-серверной части. Часть MultiLauncher (модуль SSC UZ).

Стек: **Python 3.8+ / tkinter / ttk (clam) / tksheet / pandas / openpyxl (+ pyxlsb для .xlsb)**.
Тема оформления — Catppuccin Mocha (палитра в словаре `C`).

## Как запускается
- Двойной клик по `Открыть поиск.bat`, либо `python excel_search.py`.
- Зависимости ставятся автоматически при первом запуске функцией `_ensure()`
  (`pip install pandas openpyxl tksheet` — нужен интернет). `pyxlsb` в `_ensure` **не** входит —
  ставится/нужен вручную, если открывают `.xlsb`.
- **Важно:** launcher жёстко прибит к `C:\Python314\pythonw.exe`. На машине с другим путём/версией
  Python launcher не сработает — правится строка в `.bat`.

## Логика (по разделам excel_search.py)
- **Настройки** (`load_settings`/`save_settings`): хранят `last_file`, `col_visibility` (видимость
  каждой колонки), `col_panel_width`, `checked` (отметки строк, см. ниже). Файл
  `excel_search_settings.json` рядом со скриптом, UTF-8.
- **Старт** (`App.__init__`): открывает `last_file` из настроек, иначе `DEFAULT_EXCEL` (`维修日报数据.xlsx`
  рядом со скриптом — обычно отсутствует, тогда окно пустое).
- **Режимы чтения** (radiobuttons «Лист» / «Вся книга»): один лист (`xl.parse(sheet)`) или конкатенация
  всех листов с добавленной колонкой `_Лист_` (`mode_var = "all"`).
- **Колонки** (`_rebuild_col_checkboxes`): слева чекбоксы видимости + мини-поле пофильтра на колонку
  (`col_filters`). Кнопки «Все»/«Ноль». Видимость сохраняется в настройки.
- **Поиск** (`_on_search`): live (trace на `query_var`). Глобальный запрос ищется по ВСЕМ выбранным
  колонкам одновременно (`.contains(..., regex=False)`), плюс AND по индивидуальным пофильтрам колонок.
  Флаг «Регистр» = case-sensitive. Показывается максимум **1000 строк** (`.head(1000)`).
- **Таблица** (`_show_table` / tksheet): подсветка совпадений жёлтым (`_highlight_matches`) —
  только если результат ≤ 300 строк (иначе пропускается для скорости).
- **Отметки строк** (колонка «✓», `checkbox` из tksheet): первая колонка таблицы — чекбокс
  «обработано/найдено». Отметка привязана к строке через СТАБИЛЬНЫЙ ключ = md5-хэш от ВСЕХ
  значений исходной строки (`_compute_row_keys`, служебная колонка `_Лист_` из хэша исключена).
  Поэтому отметка держится за конкретную строку независимо от её содержимого (номера, ФИО и т.п.) и
  не «переезжает» при live-фильтрации, когда состав видимых строк меняется. Идентичные строки-дубли
  получают один ключ и отмечаются вместе (это осознанный компромисс). Хранение — per-file:
  `settings["checked"][<путь файла>] = [хэши…]`. Клик обрабатывает `_on_check(event)`
  (`event.row` → `self._display_keys[row]`, `event.value` → вкл/выкл), сразу пишет в JSON.
- **Клик по ячейке** (`_on_cell_select`): значение попадает в formula bar И копируется в буфер обмена.
  Колонка «✓» (индекс 0) из копирования исключена.
- **Ctrl+A/C/V/X** (`_bind_clipboard_shortcuts`): работают на ЛЮБОЙ раскладке — биндинг по keycode
  (65/67/86/88), не по символу.
- **Авто↺** (`_auto_loop`): поток-демон, каждые 5 сек проверяет `mtime` файла, при изменении —
  перезагружает. Останов через `threading.Event`.
- **Экспорт CSV** (`_export_csv`): текущая выборка (те же колонки/фильтры), кодировка `utf-8-sig` (BOM).

## Константы / ориентиры
- `SETTINGS_FILE`, `DEFAULT_EXCEL` — рядом со скриптом (`os.path.dirname(__file__)`).
- Лимит отображения: 1000 строк. Лимит подсветки: 300 строк.
- Интервал авто-перезагрузки: 5 сек.
- Палитра — словарь `C` (Catppuccin Mocha).
- Данные заказчика (SSC UZ) — китайские заголовки: `序列号` (серийный), `物料编码` (код материала),
  `品名` (наименование), `库位` (ячейка склада) и т.д. Скрипт полностью Unicode-safe.

## Грабли и правила
- **Не трогать raw-источники**: сами Excel-файлы (`UZ missing.xlsx` и пр.) — источник истины, только чтение.
- **openpyxl read_only + битые dimensions** (глобальная грабля): экспорты FineReport/китайские выгрузки
  в `read_only=True` могут отдавать `max_row=1` (лист «пустой»). Здесь чтение идёт через
  `pd.ExcelFile(...).parse()` (не read_only) — проблема не проявляется. Если появится «исчезновение»
  строк — проверять именно этот момент.
- **Windows cp1251** (глобальная грабля): консоль машины cp1251. Все файловые операции в скрипте уже
  с `encoding="utf-8"` / `utf-8-sig`. Не ломать при правках.
- **Launcher прибит к `C:\Python314`** — см. выше.
- **`.xlsb`**: движок `pyxlsb` не входит в авто-установку `_ensure`. Открытие `.xlsb` без него упадёт.

## Критерии «готово» при правках
1. `python excel_search.py` стартует без ошибок, окно открывается.
2. Загрузка тестового `.xlsx`, live-поиск даёт совпадения, подсветка работает.
3. Настройки видимости колонок сохраняются между запусками (`excel_search_settings.json`).
4. Кириллица/китайские заголовки не бьются.
